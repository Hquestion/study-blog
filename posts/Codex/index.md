# Codex 使用

记录了解到的Codex基础知识和使用技巧。

## AGENT.md

### 用途
给不同 coding agent 提供一个稳定、可预测的项目指令入口，把项目结构、开发命令、测试要求、代码风格和协作边界显式写下来，减少反复解释。

可能包括内容：
- 对个人用户：减少重复解释“项目怎么跑、怎么测、哪些地方不能碰”。
- 对团队项目：把团队共同认可的 agent 使用规则沉淀到仓库里。
- 对多工具环境：让 Codex、IDE agent、CLI agent 等工具尽量读取同一份项目说明。

### 配置

- 用户级别配置：~/.codex/AGENT.md。将会影响所有项目
- 项目级别配置：在项目根目录下放置AGENT.md。只影响当前项目自身
- 模块级别配置：在项目某个目录下配置AGENT.md，如在apps/web下面放前端相关的规则。适合编写局部需求。

### 读取顺序

全局（~/.codex/AGENT.md）-> 项目根目录AGENT.md -> 模块下AGENT.md => 将配置从上到下合并到一起，全局在最上面，模块在最下面

> 1. 如果存在AGENT.overwrite.md，将会覆盖所在层级的配置
> 2. 可通过codex中配置`project_doc_fallback_filenames`，指定文件名称。找不到AGENT.md时，将会寻找指定的文件
> 3. Codex 还会限制合并后的项目指令大小。官方默认值是 project_doc_max_bytes = 32768，也就是 32 KiB。规则文件太大时，后面的内容可能不会进入上下文，所以尽量保持 AGENTS.md 精简。

### 本地配置
社区工具 `codex-agents-local` 提供了 AGENTS.local.md 的本地覆盖方案。它通过 Codex hooks 在会话开始或提交提示词时同步本地规则。

### 参考配置

```markdown
# AGENTS.md

## 项目概览

- 项目类型：
- 主要语言：
- 关键目录：
- 不要修改的目录：

## 常用命令

- 安装依赖：`...`
- 本地开发：`...`
- 运行测试：`...`
- 类型检查：`...`
- 格式化：`...`

## 代码规范

- 遵循现有代码风格。
- 不做无关重构。
- 新增功能必须补充或更新测试。

## 安全边界

- 不读取或提交 `.env`、密钥和私有凭据。
- 不执行删除生产数据的命令。
- 修改数据库迁移前先说明影响。

## 交付要求

- 说明改动文件。
- 说明验证命令和结果。
- 说明未验证项和剩余风险。
```
